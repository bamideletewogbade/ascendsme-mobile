## 1. Shop / Online Store

### Web Module: `src/components/ShopModule.tsx` (4,703 lines)
### Web Services: `src/lib/shop-service.ts`, `src/lib/order-service.ts`

#### DB Tables
- **`shops`** — storefront config (branding, delivery, analytics)
- **`shop_products`** — product-to-shop mapping (visibility, pricing override, featured)
- **`shop_orders`** — customer orders
- **`shop_order_items`** — line items within orders

#### Tabs
| Tab | Purpose |
|---|---|
| **Overview** | Dashboard: revenue, views, orders, conversion rate, recent orders widget |
| **Products** | List shop products. Table columns: image, name, price, stock, visibility toggle, featured toggle. Add products from inventory. |
| **Orders** | Paginated list with search. Status filter. Detail drawer with timeline + actions. |
| **Recovery** | Abandoned cart recovery. List of carts not converted. Send reminder feature. |
| **Settings** | Shop name, slug, tagline, branding (logo, hero banner, primary/secondary color), WhatsApp link, Instagram link, delivery settings (fee, free threshold, fulfillment type, description, map coords), marketplace listing toggle |

#### ShopProduct Model
```typescript
interface ShopProduct {
  id: string;
  shop_id: string; product_id: string; business_id: string;
  is_featured: boolean; is_visible: boolean; display_order: number;
  shop_price_ghs: number; compare_at_ghs: number; // sale/was price
  sale_ends_at: string; shop_description: string;
  image_urls: string[];
  is_digital: boolean; digital_file_url: string;
  is_made_to_order: boolean; lead_time_days: number;
  product?: { id, name, type, unit_price, current_stock, low_stock_threshold, sku }; // joined
}
```

#### Order Flow
1. Customer adds items to cart → `cart-service.ts`
2. Checkout → `createOrderFromCart()` in `order-service.ts`
   - Validates stock via `inventory-reservations` table
   - Creates `shop_order` row with status `pending`
   - Creates `shop_order_items` rows
   - Inserts `inventory_reservations` (reserves stock)
   - Returns checkout result with payment URL if digital payment
3. Payment → `processPaymentCompletion()` updates payment_status
4. SME manages orders: confirm → process → ready_for_pickup/dispatch → deliver
5. Order status update triggers:
   - CRM: customer interaction logged
   - Finance: receipt created if payment completed
   - Inventory: reservation fulfilled (stock decremented)

#### Delivery Fulfillment Types
- `'sme'` — SME handles delivery themselves
- `'arrange'` — Customer arranges their own delivery
- `null` — Not specified

## 2. Invoicing

### Web Module: `src/components/InvoicingTool.tsx` (4,703 lines)
### Web Services: — Uses `supabase_service` RPCs

#### DB Tables
- `invoices` — full lifecycle (create, edit, send, mark paid, void, pay link)
- `receipts` — payment records linked to invoices
- `recurring_invoice_templates` — templates auto-generated by pg_cron

#### Key Flows
| Flow | Description |
|---|---|
| **Create Invoice** | Form with customer selector, line items (description, quantity, unit price), due date, optional client email. AI-assisted via `parseInvoice()`. Creates invoice, assigns invoice_number via `get_next_document_number` RPC. |
| **Send Invoice** | Updates `client_email`, sends via email (Paystack pay link included if online payment enabled). |
| **Mark Paid** | Creates a receipt entry, updates invoice status to `paid`. |
| **Pay Link** | Generates `pay_token`, sets `online_pay_enabled=true`. Paystack-hosted page. |
| **Void** | Sets status to `void`. |
| **Proforma** | Status `proforma` with `valid_until` date. Can be converted to real invoice. |
| **Recurring** | Templates with frequency (weekly/monthly/quarterly/yearly), day_of_month/week. pg_cron generates next invoice. |

#### Invoice Statuses
`pending` → `paid` | `overdue` | `void` | `proforma`

- `pending` with past `due_date` auto-promoted to `overdue` (mobile does this client-side)

#### Key Differences from Mobile
- Web has inline editing of existing invoices
- Web has email delivery with PDF attachment
- Web shows invoice preview before sending
- Web has bulk actions (select multiple, mark paid, send reminders)

#### Tabs / Views

|---|---|

| **List** | Chronological list of all bookings. Filter by status. |

| **Portal** | Embedded public booking page preview. |

#### Booking Model (Web)
```typescript
interface Booking {
  id: string; business_id: string; service_id: string;
  client_name: string; client_phone: string; client_email: string;
  booking_date: string; booking_time: string;
  status: 'pending' | 'confirmed' | 'cancelled' | 'fulfilled';
  customer_id: string | null;
  custom_fields: Record<string, any> | null;  // extra form fields
  deposit_amount: number; deposit_paid: boolean; deposit_payment_reference: string | null;
  upselling_addons: string[];  // addon services
  reminder_sent: boolean; reminder_sent_at: string | null;
  fulfilled_at: string | null;
  invoice_id: string | null; receipt_id: string | null;
}
```

#### Booking Flows
| Flow | Description |
|---|---|
| **Create booking** | Pick service, date/time, client info. Optional: deposit, addons, custom fields. |
| **Public portal** | Public booking page at `ascendsme.africa/book/<slug>`. Customers can self-serve: select service → pick date/time → enter name + phone → book. |
| **Confirm** | Sets status to `confirmed`, optionally sends WhatsApp reminder. |
| **Fulfil** | Sets `fulfilled_at`. Can generate invoice/receipt. |
| **Cancel** | Sets status to `cancelled`. Releases inventory reservations. |
| **Deposit** | Optional deposit amount. Tracks `deposit_paid` and `deposit_payment_reference`. |

#### Mobile vs Web Gaps
- Web has public booking portal (not in mobile)
- Web has calendar view
- Web tracks deposits, addons, custom_fields
- Web has automated WhatsApp reminders
- Web links bookings to invoices and receipts

## Cross-Cutting: Offline Architecture (Mobile Only)

Web is always-online, but mobile has a complete offline-first architecture:
1. **ConnectivityService** (`connectivity_plus`) — monitors network status
2. **CacheService** — SharedPreferences-backed offline cache per domain
3. **Two-phase loading** — cache first, then network refresh
4. **SyncService** — mutation queue for offline writes, replayed on connectivity restore
5. **Offline banner** — shown during offline state

## Cross-Cutting: AI / Ascend Assistant

### Web: `supabase/functions/_shared/agents/` (Edge Functions)
### Mobile: `lib/services/ai_service.dart`

#### Web AI Tool Architecture
- Each domain has dedicated AI tools registered in the agent framework:
  - Shop: `add-to-cart`, `browse-products`, `checkout-link`
  - Finance: `draft-invoice`, `find-outstanding-invoices`, `log-expense`, `send-receipt`, `send-invoice-to-customer`
  - Booking: `book-appointment`, `check-availability`, `reschedule`
  - CRM: `find-customer`, `customer-history`, `send-segmented-campaign`
  - Documents: `extract-document`
- Tools can be called by the AI assistant to perform actions on behalf of the user

#### Mobile AI Approach
- Simpler: chat-based with `AIService.ask()` and `AIService.parseInvoice()`
- No tool-calling agent framework
- Fallback chain: OpenCode Zen (free) → Groq → OpenRouter
